## Executive Summary

This update completes a major modernization of the administrative management interface in SmartServe. The legacy Network and Security module (consisting of topology diagrams, DHCP reservation tables, ACL rule managers, packet simulation controls, and related guide modals) has been replaced with a streamlined, real-time **Users and IP Tracker** page.

In addition, the system now provides an end-to-end **Failed Login Attempts** security tracking pipeline that records and displays unsuccessful sign-in events across both student and staff/admin portals.

All user interface controls, dropdown filters, search inputs, and modal windows have been harmonized to follow the unified design language of the Menu Management module.

## 2. Dedicated Users and IP Tracker Module

### Overview
A new component, `client/src/components/admin/menu/UsersIpTrackerTab.jsx`, was created to give administrators complete visibility into all users connected to or registered within SmartServe.

### Data Aggregation and Telemetry Pipeline
- **Backend Data Fetching (`server/controllers/networkController.js`)**:
  - The `getConnectedSessions` handler queries all registered students and approved staff and administrator accounts.
  - Queries execute concurrently via `Promise.all` for optimal performance.
  - Extracts client IP addresses, resolved region, hardware form factor, and last activity timestamps.
  - Generates deterministic fallback IP addresses for accounts that have not yet established a session, ensuring 100% table population.
- **Table Structure**:
  The telemetry table displays the exact columns requested:
  1. **User / Student**: Displays avatar image (with fallback letter badge), full name, unique student ID or employee identifier, and email address.
  2. **Account Type**: Color-coded role badges differentiating Student (BYOD), Campus Staff, and System Administrator.
  3. **Assigned IP Address**: Monospace font with a one-click clipboard copy button and visual feedback.
  4. **Region**: Explicitly assigned and displayed as "Philippines" across all stations.
  5. **Device Form Factor**: Contextual hardware icon and device classification (Smartphone / Mobile, Desktop PC / Laptop, Tablet Device).
  6. **Last Activity**: Formatted timestamp with relative time calculation and a green pulse indicator for sessions active within the last 15 minutes.
  7. **Actions**:
     - **Ping**: Interactive ICMP latency test button that returns round-trip time in milliseconds.
     - **Inspect**: Opens the detailed Telemetry Profile modal.

## 7. Failed Login Attempts Tracking System

### Overview
A dedicated security tracking pipeline was implemented to record, monitor, and manage unsuccessful login attempts across both the Student and Staff/Administrator login endpoints.

### Backend Implementation
- **Database Model (`server/models/FailedLogin.js`)**:
  - Schema stores:
    - `accountType`: Classification (`student`, `staff`, `admin`, `unknown`).
    - `identifier`: Attempted School ID or username.
    - `name`: Full name of the user if found, or "Unregistered Account".
    - `email`: Associated email address if found.
    - `ipAddress`: Client IP address.
    - `region`: Standardized to "Philippines".
    - `deviceType`: Detected hardware form factor.
    - `userAgent`: Raw browser user-agent string.
    - `reason`: Specific failure reason.
    - `createdAt`: Timestamp with automatic indexing.
- **Multi-Portal Capture**:
  - **Staff and Admin Logins (`server/controllers/authController.js`)**:
    - Records events when a username does not exist, password does not match, account is temporarily locked, or account is pending administrator approval.
  - **Student Logins (`server/controllers/studentAuthController.js`)**:
    - Records events when a School ID does not exist, password does not match, account is temporarily locked, or account has been deactivated/deleted.
  - Both controllers simultaneously record entries in `AuditLog` under the `auth` category.
- **API Endpoints (`server/routes/networkRoutes.js` and `server/controllers/networkController.js`)**:
  - `GET /api/network/failed-logins`: Returns paginated records, statistical aggregates (total, student total, staff/admin total, last 24 hours), with search and filter support.
  - `DELETE /api/network/failed-logins/:id`: Deletes an individual failed login entry.
  - `DELETE /api/network/failed-logins/clear-all`: Clears the failed login attempt history.

### Frontend Implementation (`UsersIpTrackerTab.jsx`)
- **Sub-Navigation View Switcher**:
  - Added a toggle bar at the top allowing administrators to switch between **Registered Users & Telemetry** and **Failed Login Attempts**.
  - Features real-time counter badges on both buttons.
- **Summary Metric Cards**:
  - Total Failed Attempts
  - Student Attempts
  - Staff & Admin Attempts
  - Recent Attempts (Past 24 Hours)
- **Search & Filters**:
  - Search bar supporting searches by name, identifier, email, IP address, or reason.
  - Dropdown filters using `CustomFilterSelect` for Account Type and Device Form Factor.
  - "Clear Failed Logs" action button with confirmation dialog.
- **Failed Logins Telemetry Table**:
  - Columns: `User / Attempted Identifier`, `Account Type`, `Assigned IP Address`, `Region` ("Philippines"), `Device Form Factor`, `Failure Reason`, `Attempted At`, and `Actions`.
  - Color-coded badges for failure reasons (such as incorrect password, account locked, unregistered account).
- **Incident Inspector Modal**:
  - Displays full incident telemetry: origin IP, location, device hardware, failure explanation, account details, and raw browser User-Agent string.
- **Record Management**:
  - Administrators can inspect individual incidents, delete single entries, or clear all records with confirmation modals.
